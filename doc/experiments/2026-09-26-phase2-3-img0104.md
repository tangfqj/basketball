# Experiment: full-video tracking and shot detection on IMG_0104 (Phases 2–3)

| | |
|---|---|
| **Date** | 2026-09-26 |
| **Pipeline** | `hoopstats detect` (ball_v1, MPS, ~4.2 fps) → `track-ball` → `events/shots.py` v1 |
| **Ground truth** | 105 reviewed ball boxes + 5 "no ball" frames; 33 labelled shots (11 made) |

## Ball tracking (Phase 2 exit criterion)

| Split | Ball frames | Recall | Median error | "No ball" frames | False alarms |
|---|---|---|---|---|---|
| train | 75 | 97.3% | 1.6 px | 5 | 2 |
| val | 30 | 96.7% | 2.2 px | 0 | – |

All **33 / 33 shots**: the ball path covers the whole flight (release → +1.5 s) and reaches the rim.
→ Phase 2 exit criterion met on IMG_0104. (The 2 false alarms are among only 5 "no ball" frames — too few to
judge; likely the tracker bridging a short occlusion.)

## Shots (Phase 3 v1)

| | Result |
|---|---|
| Attempts | recall **33 / 33**, precision 33 / 34 |
| Make / miss | **33 / 33** (after one rule change, see below) |
| Release time | median 0.40 s earlier than the label (range 0.10–0.70 s) |

- The extra detection (373.0 s) is a real shot taken **after the final whistle** (removed from the labels on
  purpose); game-state awareness is out of scope for M1.
- One make (137.7 s) was first classified as a miss: a steep, angled entry that drifted sideways through
  the net. Rule added: a ball is also "through the net" when the net **brakes** its horizontal speed
  (|vx after| ≤ 0.5 |vx before|).

## Caveats

- The make rule was adjusted on this same video: **33 / 33 is a development score, not a test score.**
  More labelled videos are needed (IMG_0105–0108) to check it honestly.
- 11 made shots only; free throws: 2 (both missed).
- Release is systematically early (includes the shooting motion); refine with the shooter's hands in Phase 4.
